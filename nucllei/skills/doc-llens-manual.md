# LLENS マニュアル (LLENS 自身の使い方) の引き方

`/ext/doc/医療情報システム/LLENSマニュアル/` 配下。**原本はリポジトリのソースと配備そのもの**
(URL の原本も、版のある原本文書も無い)。2026-09-04 転記。

**「LLENS はこれができるか / どこで設定するか / なぜこう動くのか」は、記憶で答えず必ずここを引く。**
自分自身のことなので記憶で答えたくなるが、**画面の項目名・既定値・切り替えの場所は
記憶と実装がずれる**。実害の例: 「Enter 送信は切り替えられない」と答えたが、実際は
入力欄左の「+」→「Enter キーの動作」で切り替えられる (`/ext/doc/医療情報システム/LLENSマニュアル/04_ユーザー設定/04_チャットタブ.md` に明記)。

## 引き方 — `path` をこの木に絞る (重要)

**`grep_doc` には必ず `path="/ext/doc/医療情報システム/LLENSマニュアル/"` を付ける。**
UI の語 (「ファイル」「モデル」「設定」「実行」「上限」「一覧」) は他コーパスの一般語と衝突する。

実測: `ファイルの上限を教えて` を root 全体 (`path="/ext/doc/"`) で引くと、**1 位が医療安全管理マニュアルの
「治療部門の安全管理」**になり、本命の `/ext/doc/医療情報システム/LLENSマニュアル/03_ワークスペース/12_設定_ファイル.md` は 2 位に落ちた。
この木に絞れば 1 位に出る。

```
{"query": "Enter キーの動作", "path": "/ext/doc/医療情報システム/LLENSマニュアル/"}
{"query": "音声の文字起こし",  "path": "/ext/doc/医療情報システム/LLENSマニュアル/"}
```

- 章の見当が付いているならさらに絞ってよい
  (管理者向けの設定なら `path="/ext/doc/医療情報システム/LLENSマニュアル/03_ワークスペース/"`)
- 逆に「LLENS の話か院内システムの話か」が曖昧な問い (「ログインできない」「印刷できない」) では
  絞らずに引き、**どちらの木から返ってきたか**を見て判断する
- 画面の項目名は `「Enter キーの動作」` のように**鉤括弧つきの literal** で本文に入っている。
  短く固有な項目名で引くのが最も当たる

## LLENS ポータルの QR は本文に貼る

利用開始・アカウント作成・承認待ち・更新情報やお知らせの在処を案内するとき、`read_doc` の戻り値にある
ポータルの QR 画像 (`![図: LLENS ポータル (llens.prism-hu.org) の QR コード](…portal-qr.png)`) の markdown を
**そのまま本文に再掲する** (ポータル URL の文字列だけで済ませない)。ポータルはインターネット上にあって
院内端末からは開けず、職員はこの画像をスマートフォンで読み取って開くので、画像が案内そのもの。
再掲は `03_利用開始とログイン` か `05_問い合わせ先とフィードバック` の戻り値の literal だけを使う。
連絡先を答えるときはメール (LLENS開発チーム <redacted-email>) を引き、公式サイト <https://llens.prism-hu.org> は「更新情報・お知らせ・申し込み」
の用件のときに添える (連絡先表の「公式サイト」行が出典)。

## `/ext/doc/医療情報システム/LLENSマニュアル/` は tool / skill の「一覧」を持たない — 意図的

**「どんなツールが使えるか」「どんなスキルがあるか」「モデルは何が選べるか」を doc で数え上げない。**
配備の設定が変わると一覧はすぐ古くなり、しかも古くなったことに誰も気づけないため、
**意図的に載せていない** (`/ext/doc/医療情報システム/LLENSマニュアル/05_LLENS固有の機能/` の本文がその方針を名乗っている)。

| 知りたいこと | 画面のどこで分かるか |
|---|---|
| いま使えるスキル | チャット入力欄の**先頭で `/` を押す** (ID・名前・説明が出る) |
| 選べるモデル | チャット画面上部のモデルセレクタ |
| 配備のツール / スキル / 拡張の全体 | ワークスペース > 「ツール」/「スキル」/「拡張」の一覧 (管理者) |
| 計算式・評価スケールの収録 | 画面には出ない。`/ext/doc/医療情報システム/LLENSマニュアル/05_LLENS固有の機能/03_収録している文書.md` の「臨床スケール・計算式」 |

**doc に書いていないことを「その機能は無い」と答えない。** `/ext/doc/医療情報システム/LLENSマニュアル/` に無いのは
「一覧に類するもの」と「配備固有の具体値」であって、機能の不在ではない。
上の表のとおり**画面で確かめるよう案内する**のが正しい返し方。

配備先ごとに違う具体値 (接続先アドレス、有効な認証方式、上限値) も書ききれていない。
**具体値は開発チームに確認**するよう案内する。

## この配備での設定 (`## LLENS での設定`)

02〜04 章のノードには、この配備で確認できた事実があるときだけ末尾に `## LLENS での設定` という短い節が付く
(本文の画面説明は配備によらない一般の説明)。「この配備ではどうなっているか」を答えるときは、その節があれば本文よりそちらを優先する。

## 改訂日を持たない / 実画面が正

- **`/ext/doc/医療情報システム/LLENSマニュアル/` には改訂日が無い。** 「第◯版」に当たるものが存在せず (正はコードと配備)、
  frontmatter にも本文にも持たない。**冒頭の 2026-09-04 は転記日であって改訂日ではない**ので、
  他コーパスのように「YYYY-MM-DD 改訂」として引用しない
- **記述と実画面が食い違ったら、実画面が正。** 画面は改修されうるので、この文書は常に少し
  古くなり得る。職員の見ている画面と違うときは記述側が追いついていないと考え、実画面に従うよう
  案内する (併せて開発チームへ知らせてもらう)
- 画面の項目名は**鉤括弧つきの逐語**で引用する。言い換えると職員が画面上で見つけられない
