# 電話番号簿の引き方

`/ext/doc/院内マニュアル/電話番号簿/` 配下。3 つの配布物 (いずれも定期改訂) から構成される:

| path | 出典 | 基準日 (as_of) |
|---|---|---|
| `/ext/doc/院内マニュアル/電話番号簿/01_職員PHS/` | 院内PHS電話番号簿 (病院事務部管理課 施設企画係) | 2026-07-23 |
| `/ext/doc/院内マニュアル/電話番号簿/02_部門内線/` | 北海道大学病院 電話番号表 (管理課電気係) | 2026-07-27 |
| `/ext/doc/院内マニュアル/電話番号簿/03_オンコール・当直/` | オンコール／当直 電話番号簿 (総務課人事労務管理室労務管理係) | 2026-06-23 |

- **職員PHS**: 科・部門ごとに職員個人/役職の PHS 番号 (5 桁)。直下は `01_医科診療科` / `02_歯科診療科` / `03_中央診療施設等` / `04_看護部` / `05_…` (センター・薬剤部・事務部他)
- **部門内線**: 部門・病棟ごとの内線番号 (4 桁)。1 部門 = 1 leaf (86 leaf: 診療科・中央部門・病棟 NS/NC・事務・院内サービスまで)
- **オンコール・当直**: `01_オンコール・当直番号表` と `02_オンコール体制の運用ルール` の 2 leaf
- `04_院内PHS利用方法` (leaf): 転送等の PHS 操作方法

## 引き方

- 人名・科名・部門名から `grep_doc(query, path="/ext/doc/院内マニュアル/電話番号簿/")` が最短。ヒットした leaf を `read_doc` して番号を確認する
- **人名は姓と名の間に空白が入って収録されている** (`田中 伸哉`)。フルネームは `regex=True` にして、query を姓と名の間に `\s*` を挟んだ正規表現 `田中\s*伸哉` にする (path は `/ext/doc/院内マニュアル/電話番号簿/`)。空白なしのまま引くと当たらない。同姓が多いので、姓だけで引くのは名が分からないときに限り、候補を所属と合わせて絞る
- オンコール/当直は `01_オンコール・当直番号表` を直読みし、科×曜日のセル内の限定条件 (平日/祝日・宿直/日直) を質問の日付・時間帯に合わせて読む。体制の決まりは `02_オンコール体制の運用ルール`
- path segment は `01_` 等の番号接頭辞つき literal (番号を外さない)
- 各ノードの meta: `as_of` = 基準日。各サブツリーのノード本文の冒頭にも基準日を記載している

## かけ方の基本

- 内線番号は 4 桁。学外からはダイヤルイン対応番号 (◎) のみ <redacted> で直通
- 院内 PHS は 5 桁。内線電話からは `175 + PHS番号`、PHS 同士は番号そのまま
- 電話交換台・発信依頼: 内線 <redacted> / 救急救命用内線: <redacted>

## 回答時の注意

- 人事異動等で頻繁に変わるため、**回答には各サブツリーの基準日 (as_of) を添える**
- PHS・オンコール携帯の番号は院内業務用。**患者・院外関係者への提示や、電話口での即答をしない運用**になっている (職員や業者を装って聞き出す事例が多発)。院外向けの案内には代表・ダイヤルイン番号を使う
- 紙面の誤植疑いは直さず紙面どおり保持されており、該当ノード本文に「⚠ 取り込み時注記」として出る (例: 6-1NS/7-1NS 看護師長 PHS 同番号、皮膚科病棟内線 <redacted>／<redacted>)。注記があればそのまま伝える
- オンコール表は 2 科で 1 行を共有する箇所がある (呼吸器内科／腫瘍内科、放射線診断科／核医学診療科)
- 内線表中に 5 桁の番号が載っていたら、それは内線ではなく PHS (内線は 4 桁)
- **マニュアル本文の連絡先と番号簿が食い違うことがある。** 曝露事故 (`/ext/doc/院内マニュアル/感染対策マニュアル/14_職業感染対策/`) や緊急時 (`/ext/doc/院内マニュアル/医療安全管理マニュアル/01_緊急連絡先.md`) の手順を答えているなら、**手順側の番号を主に出し、番号簿の基準日つきの値を併記**する
