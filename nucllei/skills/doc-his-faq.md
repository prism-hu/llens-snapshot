# 病院情報管理システム FAQ の引き方

`/ext/doc/医療情報システム/FAQ/` 配下。院内イントラの FAQ 305 件
(2026-08-13 取得)。**1 ノード = FAQ 1 件**で、本文は原本の平文そのまま
(要約・言い換えをしていない)。回答は平均 106 字と短い。

**これは操作の FAQ であって診療の根拠ではない。** 臨床判断を聞かれているなら
`/ext/doc/診療ガイドライン/`、`/ext/doc/院内マニュアル/医療安全管理マニュアル/`、
`/ext/doc/院内マニュアル/感染対策マニュアル/` を引く (path はこの literal をそのまま使う)。

**LLENS 自身 (この Web UI) の操作・設定は FAQ の対象外。** 送信キー・添付・履歴・共有・音声・
サンドボックスは `/ext/doc/医療情報システム/LLENSマニュアル/` (`doc-llens-manual` skill) の担当で、
ここにあるのは電子カルテ・オーダなど院内システム側の FAQ。「ログインできない」「起動しない」は
どちらの話でもありうるので、**どちらの木から返ってきたかを見て、何のログイン/起動かを答えに書く**。

**院内イントラ由来。院外への持ち出し・外部公開・再配布をしない。**
本文には内線・PHS・業者の直通番号が直書きされている。`doc-phone-directory` と同じ扱いで、
**患者・院外関係者には提示しない** (職員や業者を装って聞き出す事例が多発している)。

## 引き方

- **短く、固有な断片で引く。ユーザーの文をそのまま投げない。**
  エラーメッセージ・画面名・ボタン名がそのまま本文に入っているので、そこを切り出す。
  実測: `初期化処理に失敗` → 1 件で当たる / `実施サイン` → 8 件で上位が全部正解。
  対して `実施サインを取り消したい` は**字面 0 件**になり、後述の loose に落ちて
  1 位が別件 (麻薬処方の中止取り消し) になる
- **戻り値の `mode` を必ず見る。** `loose` は「字面は 1 件も無かった」の合図で、
  当て方を変えるべき状態。`ignored_terms` に核心語 (`実施` `オーダ` `カルテ` `修正` 等) が
  入っていたら、**その語を含む短い複合語** (`実施サイン` `注射オーダ`) で引き直す
- **title だけで判断せず本文を読む** (title は質問の内容を正確に表しているとは限らない)
- 関連しそうなノードは 1 個で済ませない。同じ操作でも端末別に分かれている
  (実施サインは `05_実施` と `12_携帯端末` の両方にある)

## カテゴリが多重ラベルなので、章を list しても全件は出ない

原本のカテゴリは 12 種で **1 件が最大 5 個持つ**。ツリーは 1 箇所にしか置けないので
**件数が最少のカテゴリ**の下に置いてある。結果:

| | |
|---|---|
| 章 = そのカテゴリの全件 | 電子コメント / 予約 / 患者基本 / 患者看護 / PACS / 携帯端末 |
| 章だけでは足りない | 電子カルテ / 注射 / 処方 / 検査 / 実施 / オーダ |

後者は差が大きい (**オーダは原本 143 件に対し章には 36 件**、処方は 83/50、注射は 61/34)。
**「07_オーダ を list したから オーダ の FAQ は 36 件」は誤り。**

**カテゴリを網羅したいときだけ**、各リーフ本文冒頭の「カテゴリ:」行を狙う:

```
grep_doc(query="^カテゴリ: .*オーダ", path="/ext/doc/医療情報システム/FAQ/",
         regex=true, limit=50)
```

- **網羅が目的なので `limit: 50` を明示し、`has_more` が true の間 `next_offset` で回す**
  (オーダは 143 件 = 3 回)。件数だけ答えるなら `match_count` が総数なので 1 回で足りる
- `regex: true` は**この式にだけ**使う。regex では全角/半角の吸収が効かず
  (全角で書かれた番号は半角では引けない)、`^` も行頭ではなく**本文先頭**を指す。
  他の検索に `regex` を付けない — 付けない方が全角・半角・大小文字を吸収して強い
- **網羅目的では**素のカテゴリ名で引かない (本文で言及しているだけのノードや索引ノードが
  混じって件数がずれる)。**普通の検索ではカテゴリ名をそのまま使ってよい**
- `99_カテゴリ未設定` の 76 件はこの式では拾えない (`カテゴリ: (原本で未設定)` のため)

## 答えるときの注意 (このコーパス固有)

- **制限・警告の「解除手順」を述べている回答は、手順だけを渡さない。**
  併用禁忌のパスワード発行、使用者限定薬剤、麻薬施用者番号などは、FAQ が書いているのは
  **システム上の通し方**であって、通してよいかの判断は FAQ の範囲外。手順を示すと同時に
  そう明記し、`/ext/doc/院内マニュアル/医療安全管理マニュアル/` の医薬品安全使用の手順書を併せて引く
- **連絡先は原本 FAQ 掲載当時のもの。** 内線・部署名を答えるなら
  `/ext/doc/院内マニュアル/電話番号簿/` で現行値を確認する。実測で 3 種の内線は現行簿に無い。
  また **FAQ の中だけで**同じ内線に複数の部署名が付いている (組織改称の跡)。
  **多くは電話番号簿を引けば決まる** — 例えば「医療情報企画部」と「医療情報部」は
  簿に前者しか無いので前者が現行。決まらないものもある (簿にどちらの名称も無い番号)。
  いずれも **FAQ だけで部署名を断定せず、簿を引いてから答えること**。
  該当ノードには本文に注記が入っている
- **同じ事項の数値が FAQ 内で食い違うことがある** (処方の締切・時間外の境界が
  16:30 と 17:00、医事課入院係の内線が 2 通り)。時刻・締切・番号を答えるときは
  1 ノードで確定させず、同じ話題の他ノードも引く。食い違ったら両方示す
- **原本が古いままの記述がある。** 「現在」「新しいプリンタ」「修正依頼中」
  「現システム / 前システム」など**いつ時点か本文から決まらない**言い回しが混じる。
  そのまま現在の仕様として断言せず、根拠が本文のどこにあるかを示す
- **原本の回答が途中で切れているものがある** (列挙が `７）` で終わる等)。
  欠けている項目を補完・推測しない
- 回答が質問に正面から答えていないものもある。**その場合は「FAQ にはこう書いてある」と
  範囲を明示**し、足りない部分は医療情報企画部への確認を促す

## 参照資料 (PDF) と原本リンク

- 117 件が院内資料 (操作マニュアル等) を挙げている。**PDF 本体は doc に収録していない**ので、
  `read_doc` の本文にあるリンク (院内 Web の絶対 URL) をラベルごとそのまま写して案内する。中身を確かめるなら
  その literal を `fetch_url` に渡す (見た目・スキャンだけ `feed_image`。`intranet-web` skill)
- **例外**: 資料名が doc 収録済み文書と一致するものには
  `doc 収録済み: <path>` が付いている。その場合はリンクではなく**そのパスを `read_doc`
  して答える** (針刺しの FAQ が `/ext/doc/院内マニュアル/感染対策マニュアル/` を指す例がある)
- `※原本のリンクも切れている` と書いてある資料は**原本側で既に開けない**。
  「そちらを見てください」と案内しない
- 各ノード末尾に原本 FAQ ページへのリンクがある。開けなかったときは `ERROR:` の事実の文 (「次の手:」より前) を書かれたとおりに伝える。
  **開けないことは FAQ の記述が古い証拠ではない** (リンク先は配備先ごとに違う)
