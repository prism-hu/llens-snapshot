## 引き方 (点数表)

- 区分番号が分かっているなら `grep_doc(query="Ｋ６５５", path="/ext/doc/診療報酬/")` で場所を特定してから `read_doc`。**特掲診療料は階層が深く、path を組み立てられない** (下記)
- 名称・キーワードからは `grep_doc(query, path="/ext/doc/診療報酬/医科点数表R08_特掲診療料/")`
- **path を区分番号の字面から組み立てない。** 枝番が 2 段あるもの (`Ｂ００１－２－２`) や半角混じり (`Ｂ００１－10`) があり、組み立てると外す
- 各ノードは `## 告示 (点数と注)` → `## 留意事項通知 (算定要件)` の順。**両方読んでから答える。** 点数は告示、算定できる条件・回数・併算定の可否は通知にある
- 長い区分では `告示` / `留意事項通知` / `コード表` が**子ノードに分かれている**。親の本文がその path を名乗るので、必要なものだけ開く
- **各区分ノードの頭の「収録範囲の案内」が、その区分に対応する施設基準ノード・疑義解釈ノード・登録者一覧ノードの path を名乗る** (対応が無いときは「無い理由」と次の一手)。**そこに書かれた path をそのまま read する**のが最短で、字面から組み立てない

### 特掲診療料の階層

部 → (節 → 款 → 群) の順に、**必要なところだけ**深くなっている。

```
/ext/doc/診療報酬/医科点数表R08_特掲診療料/
  B_医学管理等 … O_その他            ← 14 の部
  K_手術/第01節_手術料/第09款_腹部/群03_胃、十二指腸/K646_….md   ← 最深
  D_検査/第01節_検体検査料/…
```

`M_放射線治療` のように区分が少ない部は直下にリーフが並ぶ。**どこまで深いかは部によって違う**ので、`list_doc` で辿るか `grep_doc` で直接当てること。

### 部と区分番号の対応

`B` 医学管理等 / `C` 在宅医療 / `D` 検査 / `E` 画像診断 / `F` 投薬 / `G` 注射 / `H` リハビリテーション / `I` 精神科専門療法 / `J` 処置 / `K` 手術 / `L` 麻酔 / `M` 放射線治療 / `N` 病理診断 / `O` その他

### 通則

**通則 (章・部・節・款・群ごとの前置き条文) は全部入っている**。
算定の骨なので、**区分のノードだけ読んで答えると条件を落とす**。

置き場は「その階層のディレクトリ → 無ければ直近の親ディレクトリ → それも無ければセクションの入口」:

- **部の通則** … 部のディレクトリ (`…/<部>/`) の本文 (`## 告示の通則` / `## 留意事項通知の通則`)。
  第2章の 14 部 (`B`〜`O`) は全部そろっている
- **節・款・群の通則** … その階層のディレクトリがあればそこ、**無ければ直近の親ディレクトリ**の
  本文に `## 留意事項通知の通則 — 第1節 エックス線診断料` の形で入っている。
  節・款をディレクトリに切っていない部 (`E` 画像診断・`G` 注射・`N` 病理診断・`I` 精神科専門療法) の
  節通則は部のディレクトリの本文に、`C` 在宅・`D` 検査の款通則は節のディレクトリの本文にある
- **第1章 基本診療料の通則** (第1部 初・再診料、第2部 入院料等、第2節 入院基本料等加算、
  第3節 特定入院料) … 第1章は階層ディレクトリを持たないので、
  **`/ext/doc/診療報酬/医科点数表R08_基本診療料/` (セクションのディレクトリの本文) の
  「このセクション全体に効く前置き条文」**に告示・通知ともまとめて入っている
- **留意事項通知の冒頭の総則** (全章に効く 1〜9。費用の総計の出し方・基本診療料に含まれる簡単な
  検査や処置・施設基準の根拠告示・署名と押印など) … **`/ext/doc/診療報酬/医科点数表R08_基本診療料/` に
  1 箇所だけ**置いてある (`## 留意事項通知の総則 (全章共通)`)。第2章・第3章の入口はそこを指すだけ
- **第2章 特掲診療料の冒頭の通則** … `/ext/doc/診療報酬/医科点数表R08_特掲診療料/` の本文
- **第3章の前置き** … `/ext/doc/診療報酬/医科点数表R08_介護老人保健施設入所者/` の本文
  (第1部・第2部の本文は各部のノード)
- **第4章 経過措置** (精神病棟入院基本料 18対1/20対1 の当分の間の算定、精神科地域包括ケア病棟入院料の
  通算) … 中身が第1章の話なので `/ext/doc/診療報酬/医科点数表R08_基本診療料/` の本文に
  `## 告示 第4章 経過措置` として入っている

**入っていないもの** — ここだけは原本を見ること:

- **別表1「第1節入院基本料、第3節特定入院料及び第4節短期滞在手術等基本料との関係」**
  (入院基本料等加算が特定入院料に包括されるかの一覧表)。原本が横に 200 列以上ある表で、
  収録していない。**加算が包括されるかを表で確かめたいときは
  留意事項通知の原本 (PDF の末尾) を見るよう案内する**
- **別添1の2 の別紙様式**。通知本文が「書面等は別紙様式のとおり」と送っているだけで、様式そのものは
  入っていない

## 「当院で算定できるか」 — 必ず 3 つ read する

順番も固定。**どれか 1 つだけで結論を出さない。**

1. **点数表** (`/ext/doc/診療報酬/医科点数表R08_基本診療料/` か `…特掲診療料` の区分ノード) — 点数と算定要件。告示の注に「別に厚生労働大臣が定める施設基準に適合しているものとして…届け出た」とあれば施設基準の届出が要る
2. **施設基準の中身** (`/ext/doc/診療報酬/施設基準R08_基本診療料/` = 第1章分 / `/ext/doc/診療報酬/施設基準R08_特掲診療料/` = 第2章分) — 人員・体制・実績の要件。点数表ノードの「収録範囲の案内」が対応ノードの path を名乗る。無ければ施設基準名で `grep_doc(query="<名称>", path="/ext/doc/診療報酬/施設基準R08_特掲診療料/")` (点数表と施設基準は**名称**で突き合わせてあり、結び付いていない区分がある。**path が無い = 施設基準が無い、ではない**)
3. **当院の登録状況** (`/ext/doc/院内マニュアル/施設基準届出状況/`) — 施設基準ノードが対応ノードの path を名乗る (双方向)。ここで**言い方を間違えると事故る**:
   - `/ext/doc/院内マニュアル/施設基準届出状況/` は**施設基準ごとに専任・専従で登録している職員の名簿** (令和8年7月時点) であって、**当院が届け出ている施設基準の一覧ではない**
   - **載っていない = 届け出ていない、ではない。** 職員配置を要しない施設基準 (地域加算・療養環境加算・設備要件など) は届け出ていても載らない
   - **載っている = 算定できる、でもない。** その施設基準に向けて職員を登録している (届出済みか準備中) と読めるだけ。令和8年7月時点の登録なので異動で変わる
   - 結論は「点数表の要件はこう、施設基準はこう、登録者一覧には◯◯科の△名が専任で登録されている (令和8年7月時点)。**届出の有無と現時点の充足は 医事課施設基準係 に確認**」の形にする。「算定できる」「届け出ていない」を断定しない

施設基準ノードだけ読んで「基準を満たしているので算定可」と言うのは**当院の状況を見ていない**回答なので不可。逆に登録者一覧だけ読んで「登録があるので算定可」も不可 (施設基準の他の要件・点数表の算定要件を見ていない)。

## 疑義解釈 (Q&A) の引き方

- **収録は その12 (2026-09-02 発出) まで。** 必ず「その N 問 M」と収録時点を添えて答える。それ以降の その N は未収録なので、「最新の疑義解釈では」と言わない — 特設ページを案内する
- 区分番号が分かるなら `/ext/doc/診療報酬/疑義解釈R08/<部>/<区分ノード>` (点数表側と同じ basename。点数表ノードの「収録範囲の案内」が path を名乗る)。1 ノードにその区分の問が発出順に全部入っている (`### その5 問7` の見出し)
- 区分番号を書かない問 (届出手続き・様式・通則・特別食加算・特定保険医療材料など) は `/ext/doc/診療報酬/疑義解釈R08/区分番号なし/` に原本の 【見出し】 ごと。**区分ノードが無い = 疑義解釈が無い、ではない** — 名称で `grep_doc(query, path="/ext/doc/診療報酬/疑義解釈R08/")` してから「無い」と言う
- 複数の区分に触れる問は**最初に出た区分**の下に 1 箇所だけ置かれている (各問の「問に出る他の区分」に残りの path)。網羅したいときは grep
- **O 部 (看護職員処遇改善評価料・ベースアップ評価料) は特殊。** 問が区分番号を書かず (Ⅰ)(Ⅱ)・入院を並べて語るため、**最初に出た評価料の区分にしか置かれていない** (O001 に付いた問の大半は O002 / O003 にも効く)。O000〜O003 のどれかを聞かれたら **`/ext/doc/診療報酬/疑義解釈R08/O_その他/` の 4 ノードを全部 read するか grep** すること。1 ノードだけ読んで「この評価料には疑義解釈が無い」と言わない
- **【廃止】** の付いた問は廃止前の内容を残してあるだけ。現行の解釈として使わない。**【訂正あり】** は訂正後の本文
- 答は告示・通知・施設基準通知の**解釈**で、点数と算定要件の正典は点数表ノード。答だけで算定可否を断定しない

## 答えるときの注意

- **必ず「令和8年度改定 (2026-06-01 適用)」を添える。** 点数は改定で変わるので、版を名乗らない回答は誤用される。疑義解釈は「その12 (2026-09-02) まで」、登録者一覧は「令和8年7月時点」も添える
- **当院は DPC 対象病院。入院料等 (第1章 第2部の入院基本料・加算・特定入院料) を包括払いの患者に日ごとに足して「入院費」にしない。** 診断群分類に該当する一般病棟の患者は 1 日あたり包括点数 × 医療機関別係数で、入院料等の多くはそこに含まれる (入院料等のリーフの頭がその旨を名乗る)。14 桁コード・期間Ⅰ/Ⅱ/Ⅲ・包括範囲・係数は `doc-dpc` skill (`/ext/doc/診療報酬/DPC点数表R08/`) をロードして引く
- **点数をそのまま金額にしない。** 1 点 = 10 円だが、患者負担は負担割合・保険種別で変わる。聞かれても点数までにとどめる
- **減算を加算として読まない。** 「◯◯点減算」「◯％減算」があり、ノードの表では書き分けてあるので表記のまま伝える
- 算定要件の判断 (この患者でこの加算が取れるか) は**要件の本文を引用して示すところまで**にし、可否を断定しない。施設基準の充足と届出の有無は上の 3 read でも「登録者一覧の時点の名簿」までしか分からないため
- **通知が無い区分が 1,130 ある** (原本がそうで、告示だけで完結している)。「通知が無い」とそのまま伝え、告示の注と施設基準ノードを根拠にする

## コード単位で網羅的に調べたいとき (CSV + run_python)

コード単位の網羅・数値条件 (「この名前を含む診療行為を全部」「点数がいくら以上のもの」) は doc では引けない (doc は区分単位)。医科診療行為マスターの原本 CSV を sandbox の pandas で直接読む (取り込みは不要)。

```
原本 CSV: /ext/doc-static/shinryo_hoshu/s_20260901.csv
```

原本そのものをユーザーに渡したいときは、上のパスは同じ文字列が配信 URL なので、その literal をそのままリンク先にして `[ラベル](…)` で本文に書く。

**cp932・ヘッダ行なし・11,831 行 × 150 列。** 列は 0 始まりの位置で引く:

| 列 | 中身 |
|---|---|
| 2 | 診療行為コード (9 桁) |
| 4 | 漢字名称 |
| 10 | **点数識別** — `3`=点数 / `6`=％ / `8`=**減算する点数** |
| 11 | 点数 (`8` なら減算幅、`6` なら％) |
| 84 | 区分番号のアルファベット部 (`A` / `B` … ) |
| 89 / 90 / 91 / 92 | 章 / 部 / 区分番号 / 枝番 |
| 86 / 87 | 変更年月日 / 廃止年月日 (`99999999` = 無期限) |

```python
df = pd.read_csv("/ext/doc-static/shinryo_hoshu/s_20260901.csv", encoding="cp932", header=None, dtype=str)
hit = df[df[4].str.contains("乳幼児加算", na=False)]
print(len(hit))   # 件数だけ出す。全行を print しない
```

- **`10` を無視すると符号が逆になる。** 素朴に読むと「200点減算」が「+200点」に、「85％」が「85点」になる
- 区分番号は `84 + 91 + 92` で復元する。**`91` だけで括らない** — `Ａ２３１` は削除済みで、実体は `Ａ２３１－２`(強度行動障害) `－３`(依存症) `－４`(摂食障害)
- CSV には**算定要件の文章が 1 文字も無い**。条件を聞かれたら doc に戻る
- **`86` は「変更年月日」であって改定日ではない**。将来日付の行がある
- CSV は改定後も随時更新される。ファイル名の日付が収録時点
- 本文に出すのは件数と数例まで。全行・DataFrame 全体を print しない (context に全行を展開しないため。個人情報の制約ではない)。一覧を求められたら作業場所で CSV にし、それを `/workspace/exports/` へ写して渡す
