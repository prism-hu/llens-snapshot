# 院内 Web を辿る (fetch_url)

`fetch_url` は院内イントラのページを 1 枚ずつ取ってきて平文 + リンク一覧にする tool。
**doc に無い院内情報を辿るための道具**であって、収録済みコーパスの代わりではない。

## まず: doc に収録済みのものは web を叩かない

院内の資料でも doc に収録済みのもの (どれが収録済みかは各カテゴリ skill (`doc-crosscut` を除く `doc-*`) の description が名乗る) は、
その skill をロードして **`grep_doc` / `read_doc` で引く** (本文が整理されていて検索も効く。web を叩くと同じ内容を遠回りで取ることになる)。
`fetch_url` を使うのは、**それ以外**の院内文書 (運用マニュアル、お知らせ・配付資料、申請書類、クリティカルパス等) を探すときだけ。

## 1 ページの読み方

実体ページ・PDF は開くまで中身の量が分からない (索引ページは 1 枚で数万〜数十万字)。
`fetch_url` は 1 回に一部 (`limit` 字) だけを返し、戻り値のヘッダに分量、続きがあれば `next_offset` が出る。

- 索引ページ (下の地図) は**必ず `query` を付けて**該当行だけを引く
- 実体ページは先頭から読み、答えに要るところまで `offset=<next_offset>` で続きを取る (要らない続きまで読み切らない)
- url は**組み立てず**、戻り値のリンク一覧に出た絶対 URL の literal をそのままコピーする (例外は下の「起点の地図」の入口 1 枚だけ)

## 起点の地図 (2026-09-04 実測)

院内 Web の原本 URL は**スキーム付きの絶対 URL**。入口のページ URL は配備先で違う:

| 配備 | 入口 URL |
|---|---|
| 本番 (病院のネットワーク。DNS が無いので IP 直) | `http://<redacted-ip>/his-info/top.aspx` |
| 開発・検証機 (大学のネットワーク) | `https://<redacted-intranet-host>/his-info/top.aspx` |

入口の 1 枚だけは、この URL の `top.aspx` を下の表のページ名に置き換えて使ってよい (組み立ててよいのはこの 1 枚だけ)。
2 枚目からは戻り値のリンク一覧に出た URL をコピーする。片方が接続できない・名前解決不可で止まったら
もう片方の配備に居る (両方を順に試してよい)。ページはどれも `top.aspx` と同じ階層:

| ページ | 中身 | 分量 | 到達 |
|---|---|---|---|
| `top.aspx` | 入口。PDF ランチャ + マニュアル一覧 | 平文 11K 字 / リンク 26 | ランチャは直リンク。**マニュアル 21 本は postback = 辿れない** (ラベルだけ本文に出る) |
| `unyou_mn.aspx` | 運用マニュアル | 275 件 / 109K 字 | 全部直リンク |
| `annai.aspx` | お知らせ・配付資料の全履歴 (2005〜) | 1,536 件 / 553K 字 | 全部直リンク。**必ず `query` を付ける** |
| `sinsei.aspx` | 申請書類 | 63 件 / 24K 字 | 全部直リンク |
| `c_pass.aspx` | クリティカルパス (科別) | 391 件 / 117K 字 | 全部直リンク |
| `faq.aspx` | 病院情報管理システム FAQ | 305 件 | postback のみ。**doc に収録済みなのでそちらを引く** |

`unyou_mn.aspx` / `c_pass.aspx` はカテゴリごとに折りたたまれて見えるが、**全カテゴリの
リンクが最初から 1 枚の HTML に載っている** (畳んで見せているだけ)。カテゴリを開く操作は要らない。

## `query` の効き (annai.aspx での実測)

無指定だと 553K 字が返る。**索引ページには必ず付ける**:

| query | 返る量 |
|---|---|
| `"施設基準"` | 2 行 / 347 字 |
| `"DPC"` | 30 行 / 5,017 字 |
| `"診療報酬"` | 38 行 / 6,683 字 |
| `"レセプト"` | 0 行 (この一覧には無い) |

- 大小文字・全角半角は無視される
- 短く固有な語で引く。0 行なら語を変える (長い文をそのまま投げない)

## 戻り値の URL は 1 本

リンク一覧の 1 行はこの形:

```
[12] 院内PHS電話番号簿 [2026年9月1日] → http(s)://<ホスト>/his-info/log_write.aspx?…
```

この URL が**次の `fetch_url` / `feed_image` / `send_to_workspace` に渡すもの**であり、
**職員に案内するもの**でもある (原本そのものの URL。職員のブラウザがそのまま開く)。
**1 文字も変えずにコピーする**。組み立てない。URL であってファイルパスではないので
`run_python` / `run_shell` に渡さない (jail はネットワーク不可)。

## 答えには必ず原本 URL を添える

読んだページ・PDF の原本 URL を `[ラベル](URL)` の形で答えに添える (ラベルはリンク一覧の行の名前、URL はその行の literal を 1 文字も変えずに)。

理由: PDF を要約して渡すと、要約の誤り・古い版・抜けがそのまま職員の判断材料になる。
**原本を開いてもらえば、正しさの責任は文書に戻る。** 院内文書は改訂が頻繁で、
こちらが読んだ版が最新とは限らない。要約は「どれを開けばよいか」を絞るためのものと考える。

## 辿れないもの (先に知っておく)

- **postback (`__doPostBack`) のリンクは辿れない。** `top.aspx` のマニュアル 21 本と
  `faq.aspx` がこれ。ラベルは本文に出るがリンク一覧には出ない。
  「一覧に見えているのに URL が無い」ときはこれ。**職員には `top.aspx` の原本 URL を案内し、
  そこから開いてもらう**
- **末尾が `/` のディレクトリは 302 で転送される** (redirect は 3 回まで辿る)。辿れないと返ったら
  `http(s)://<ホスト>/his-info/top.aspx` のようにページを直接指す
- **Excel / Word などは平文にできない。** `fetch_url` は ERROR と原本のリンクを返す。
  中身が要るなら `send_to_workspace(url=…)` に同じ URL を渡して取り込み、sandbox で読む
  (Word は skill `file-conversion` の手順で文字にする)。要らなければ原本 URL を職員に案内する
- **画像は平文にできないが行き止まりではない。** `fetch_url` が画像だと言ってきたら
  `feed_image(url=…)` に同じ URL を渡して自分の目で見る。
  中身を確かめずに原本 URL だけ返さない
- **run_python で処理したい**とき (CSV・Excel の集計等) は `send_to_workspace(url="…")`
  に同じ URL を渡して sandbox に取り込む。`feed_image` は「目で見る」、`send_to_workspace` は「計算する」
- **テキスト層の無いスキャン PDF** は `fetch_url` が「テキスト層が無い」と返す。
  そのときは `feed_image(url=…)` に**同じ URL を渡せば自分の目で見られる**
  (his-info の資料リンクは全部 `log_write.aspx?…` 経由でパスが `.pdf` で終わらないが、
  `feed_image` は取得した content-type で判定するのでそのまま渡してよい。
  特定ページを見るときは `pages="3"` / `"4-7"`)。見ても読み取れないときだけ原本 URL を案内する

## 扱いの注意

院内イントラ由来の情報は**院外への持ち出し・外部公開・再配布をしない**。
内線・PHS・業者の直通番号が本文に直書きされていることがあり、`doc-phone-directory` と
同じ扱いで**患者・院外関係者には提示しない** (職員や業者を装って聞き出す事例が多発している)。
